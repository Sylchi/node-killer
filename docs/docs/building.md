# Building

QuickJS uses [CMake] as its build system. `scripts/build.js` is a small Node.js
driver that configures CMake and builds the targets below; it needs Node.js 18
or newer and nothing else.

:::note
Windows users will need to run the CMake commands manually.
:::

## Getting the source

```bash
git clone https://github.com/quickjs-ng/quickjs.git
cd quickjs
```

## Compiling everything

```bash
node scripts/build.js
```

On Linux this builds `build/qnode`, a Node.js-compatible runtime. zlib, mbedTLS,
libsodium, libev, wasm3 and QuickJS itself are vendored and linked from static
archives under `vendor/`, so no system packages or download step are required.
The archives need zig to supply the C library; on x86-64 the checked-in
`vendor/zig/zig` is used automatically, otherwise `zig` is taken from `PATH`.

When zig or a matching archive set is missing, the same command builds
`build/qjsc` instead and prints why qnode was skipped.

Head over [here](./cli) for instructions on how to use `qjs`.

On Linux there are no build options for the runtime features: WebAssembly
(wasm3), libev, zlib, mbedTLS and libsodium are always compiled in. The
vendored mbedTLS supports TLS 1.2 and TLS 1.3.

## Build targets

```bash
node scripts/build.js qnode        # qnode only
node scripts/build.js qjsc         # qjsc only
node scripts/build.js configure    # configure without building
node scripts/build.js clean        # remove objects, keep the configuration
node scripts/build.js distclean    # remove the build directory
```

`--build-dir`, `--build-type`, `--jobs` (or `-j`) and `--verbose` are accepted
after the target. The same names are read from `BUILD_DIR`, `BUILD_TYPE` and
`JOBS`:

```bash
node scripts/build.js --build-type=Debug -j 8
BUILD_TYPE=Debug node scripts/build.js
```

Every target is also an npm script, so `npm run build`, `npm run qnode`,
`npm run test`, `npm run clean` and the rest of the list above work too, and
`npm run build -- --jobs 8` forwards options to the driver.

## Tests

```bash
node scripts/build.js qnode-test        # all qnode suites
node scripts/build.js net-test          # net_shards only
node scripts/build.js netstack-tun-test
node scripts/build.js netstack-tap-test
```

## Big Endian architecture support

When compiling for a big endian target the bundled bytecode must be regenerated.
The generated bytecode is endian dependent and the currently shipped source
builds have little endian bytecode. To regenerate it:

```bash
node scripts/build.js codegen
```

Then proceed with a normal build.

## Debug builds

```bash
node scripts/build.js debug
```

This produces a debug build without optimizations, suitable for developers.

[CMake]: https://cmake.org
